# ProcMem2Skills (English)

## 1. Overview

ProcMem2Skills studies how to transform multi-trial agent trajectories into:
- benchmark-scoped procedural workflows,
- clustered and deduplicated memories,
- atomic skills generated by LLM skill creation.

The default philosophy is **batch-rollout-first**:
1. Collect trajectories across tasks and trials.
2. Induce workflows from traces.
3. Distill memories/skills through controlled pipelines.
4. Re-run agents under different memory injection settings.

## 2. Current Layout

```text
src/procmem2skills/          core package
scripts/server/              runnable server entrypoints
scripts/server/study/        short aliases for daily usage
tests/                       unit tests
docs/                        design and experiment docs
history/code/                archived legacy code
history/results/             archived historical outputs
experiments/                 active output root (empty by default)
```

## 3. Recommended Entrypoints (Short Paths)

- Controlled workflow→skill study:
  - `python scripts/server/study/controlled/run.py --help`
- Full workflow induction:
  - `python scripts/server/study/induce/workflows.py --help`
- Unified formal experiment:
  - `python scripts/server/study/formal/run.py --help`
- SkillsBench Harbor run:
  - `python scripts/server/study/live/skills.py --help`
- Terminal-Bench Harbor run:
  - `python scripts/server/study/live/terminal.py --help`
- Terminal-Bench transfer study:
  - `python scripts/server/study/transfer/run.py --help`

Long legacy names are still available for compatibility, but short aliases are preferred.

## 4. Naming Policy

To avoid very long path names in Harbor jobs and experiment output directories:
- experiment id normalization now uses tighter limits,
- Harbor job names are compacted with benchmark/phase/model slugs,
- transfer matrix launch scripts apply stricter slug truncation.

## 5. Archive Policy

Historical content is moved to `history/`:
- old server legacy scripts: `history/code/scripts/server/legacy/`
- old experiment outputs: `history/results/experiments-20260330/`
- old generated SkillsBench copies: `history/results/benchmarks/skillsbench/`

## 6. GitHub Publishing (Code-Only)

The `.gitignore` is configured to exclude:
- experiment outputs (`experiments/`, `results/`, `artifacts/`),
- datasets/benchmarks and local caches,
- all archived history (`history/`).

This keeps the push lightweight and reproducible while preserving runtime compatibility.
